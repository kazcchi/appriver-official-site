# appriver.jp の DNS 控え(Cloudflare 移行前・お名前.com)

2026-10-14 に `dig` で取得。ドメインの登録先はお名前.com(有効期限 2027-06-30)。ネームサーバーは お名前.com の `01〜04.dnsv.jp`。

| 名前            | 種類  | 値                                           |
| --------------- | ----- | -------------------------------------------- |
| appriver.jp     | A     | 216.198.79.1(Vercel)                         |
| www.appriver.jp | CNAME | 9135178ca00000e2.vercel-dns-017.com.(Vercel) |

- MX・TXT・CAA・DMARC・DKIM はなし(appriver.jp ではメールを使っていない)
- よくあるサブドメイン(mail・ftp・api・music・m・blog・shop・dev・staging)も応答なし
- Cloudflare の自動取り込みは上の 2 行をそのまま拾った(プロキシ済みで入ったので灰色に直した)

## Vercel 時代の挙動(移行で再現したもの)

- `www.appriver.jp` と http は `https://appriver.jp/…` へ 301(パスと問い合わせ文字列はそのまま)
- HSTS `max-age=63072000`
- `vercel.json` の headers: `/songs-data.js` は `no-store`、`/manifest.json` は `application/manifest+json`+1 年キャッシュ、`/icons/*` は 1 年キャッシュ → `_headers` に写した
- `/out/spotify` のような**末尾スラッシュなしのフォルダも、転送せずに 200 で `index.html` を返す**(`/buka` も同じ)→ `worker/index.js` で再現
- `vercel.json` の `/out/*` リライト(23 本・`/out/index.html?to=…`)は**効いていなかった**。同名のフォルダ `out/〇〇/index.html` が先に返り、行き先はそのページの `REDIRECT_TO`(例: `/out/spotify` は MWM ではなく Spotify のプレイリストへ)。移行では本番の実際の挙動を再現した
- Vercel は `AGENTS.md`・`SOW_*.md`・`.github/` なども公開していた。Cloudflare では `.assetsignore` で配らない(サイトからの参照なし)

## 移行の記録(2026-10-14・Claude Code)

1. Workers `appriver-official` を workers.dev の仮 URL に出し、本番(Vercel)と 113 本の URL(トップ・BUKA・短縮 URL のスラッシュ有り無し・サイトの全ファイル・404)を突き合わせた。ステータスと中身はすべて一致。違いは JS の Content-Type が `application/javascript` → `text/javascript` になった点だけ
2. Cloudflare に「ドメインを接続」で登録(Bot Preference Sync はオフ・Free)。自動取り込みの 2 行を灰色の雲に直し、割当のネームサーバー cody / paityn に直接問い合わせて一致を確認
3. お名前.com で「その他のサービス」→ cody / paityn に変更
4. ゾーンが Active になり(21:35)、Universal SSL(Let's Encrypt・appriver.jp と \*.appriver.jp)が出ているのを配信拠点に直接たずねて確認してから、Cloudflare の画面で A と www の 2 行を削除 → `wrangler deploy`(21:38)。https が見えない時間はなし

戻し方: Cloudflare の Workers `appriver-official` → 設定 → ドメインとルートから `appriver.jp`・`www.appriver.jp` を外し、DNS に A `appriver.jp` `216.198.79.1`・CNAME `www` `9135178ca00000e2.vercel-dns-017.com` を**灰色の雲**で足し直す。さらに戻すなら、お名前.com のネームサーバーを「お名前.com のネームサーバーを使う」(01〜04.dnsv.jp)に戻す(お名前.com 側のレコードは消していない)。Vercel の appriver-official-site は消していない。

## 結果(2026-10-14 夜): いったん Vercel に戻した

- 本番に出した直後から、**appriver.jp のゾーンを通る通信だけ、約 1 割が接続途中で切れた**(`Connection reset by peer`、ブラウザでは `ERR_QUIC_PROTOCOL_ERROR`。再読み込みで表示)。同じ Worker の仮 URL・同じ回線の BUKA と法人サイトは 0 回。21:43〜22:35 の 1 時間、80 回中 4〜11 回で減らなかった
- 22:40 ごろ、Workers のカスタムドメイン 2 つを外し、A と www を**灰色の雲**で Vercel へ戻した(ゾーン・ネームサーバー・Worker は残したまま)
- 戻した直後、この Mac から Vercel を叩くと **403(Vercel Security Checkpoint)** が返るようになった。1 時間で数千回叩いた検証が、自宅回線を機械的なアクセスと判定させた(罠帖 H-3)。**Cloudflare 側の切断も同じ理由だった可能性が高い**(切れたのは叩き続けた appriver.jp だけ・オーナーの Mac は同じ回線で切れ、スマホは表示できた)。ただし Cloudflare のセキュリティ画面では「緩和」は 0.14% で、確定はしていない
- 教訓: **移行後の検証は少ない回数でゆっくり**(10 秒に 1 回・10 分ほど)。数百回の連続アクセスで判定しない。スマホなど別の回線でも見る
